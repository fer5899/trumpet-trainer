## Environment Setup Script (`create-environment.sh`)

The `create-environment.sh` script generated by `/t-implement` should set up the following for manual validation. The developer machine is Windows and the script runs in Git Bash, so use POSIX shell only.

### Services to Start

1. **Vite dev server** (the whole app; there is no backend)
   ```bash
   npm ci
   npm run dev -- --port 5173 --strictPort &
   until curl -sf http://localhost:5173/ > /dev/null; do sleep 1; done
   echo "Trumpet Trainer running at http://localhost:5173/"
   ```
   - The microphone requires a secure context. `http://localhost` qualifies, but a LAN IP does not. To test on a phone, use the deployed GitHub Pages build or an HTTPS tunnel.
   - Optional deterministic mode for checking the flow without a real trumpet: `npm run dev:e2e` (sets `VITE_E2E=true`). Then open e.g. `http://localhost:5173/?melody=71,71,71,71,71` (five written Si4 = concert A4 440 Hz).

2. **Production build preview** (optional, to check the GitHub Pages build and `base` path)
   ```bash
   npm run build
   npm run preview -- --port 4173 --strictPort &
   until curl -sf http://localhost:4173/trumpet-trainer/ > /dev/null; do sleep 1; done
   echo "Production preview at http://localhost:4173/trumpet-trainer/"
   ```

### Seed Data

No seed data required for basic validation. For automated or headless checks of the listening loop, generate the fake-mic tone fixture:

```bash
npm run generate:tones   # writes e2e/fixtures/tone-a4-440hz.wav (440 Hz sine, 4 s, looping)
```

Manual validation needs a real B♭ trumpet (or any instrument or tone generator playing the concert pitch) plus speakers and a microphone.

### Cleanup

The script must provide a cleanup function using `trap ... EXIT` that:
- Kills all background processes started by the script (Vite dev server and/or preview server)
- Leaves `dist/`, `test-results/`, `playwright-report/` and `e2e/fixtures/*.wav` in place; they're gitignored, so no removal is needed

### Environment Variables

No environment variables are needed for the normal dev server. The e2e/deterministic mode reads `VITE_E2E` from `.env.e2e` through `vite --mode e2e`. To set it explicitly:

```bash
export VITE_E2E=true   # enables the ?melody= test hook; never set for production builds
```
